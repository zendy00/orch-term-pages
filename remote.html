원격 오크텀

집 PC와 회사 PC의 오크텀을 Tailscale 위에서 짝지어, 한쪽 PC의 claude·codex가 다른 쪽 PC의 에이전트와 메시지와 파일(스크린샷·로그·큰 파일)을 주고받게 합니다. Windows와 macOS를 서로 섞어 쓸 수 있습니다.

이 기능은 1단계입니다. 원격 터미널·원격 탐색기 같은 화면 원격 제어는 아직 없습니다. 지금은 에이전트 메시지와 파일만 오갑니다. Linux에서는 이 기능이 꺼져 있습니다(설정에 항목이 보이지 않습니다).

무엇을 하는가

  • 받는 PC(호스트)와 하는 PC(클라이언트)가 있습니다. 모든 오크텀이 둘 다 될 수 있고, 방향마다 따로 짝짓습니다.
  • 「이 PC로 원격 접속 받기」는 기본 꺼짐입니다. PC마다 직접 켜야 문이 열립니다.
  • 켜면 Tailscale 주소에만 연결을 받습니다(포트 9620). 사내망·LAN·인터넷에는 열리지 않고, Tailscale을 못 찾으면 켜지지 않습니다.
  • 짝지은 PC의 에이전트끼리는 chat_who·chat_send·chat_inbox(메시지), chat_send_file(파일)을 씁니다. 에이전트 채팅과 같은 도구입니다.

준비 1 — Tailscale 설치

  1. 두 PC에 Tailscale 설치·로그인

    두 PC 모두 tailscale.com/download에서 설치하고 같은 tailnet에 로그인합니다. 각 PC에 회사-win, home-mac 같은 Tailscale 이름이 붙습니다. 짝지을 때 이 이름(또는 100.x.y.z 주소)을 씁니다.

준비 2 — Tailnet Lock 켜기 (권장)

Tailscale은 PC를 tailnet에 들이는 일을 Tailscale 서버가 도와줍니다. 그 서버나 내 Tailscale 계정이 뚫리면 공격자가 내 tailnet에 가짜 PC를 끼워 넣을 수 있습니다. Tailnet Lock을 켜면 새 PC는 이미 믿는 내 PC가 서명해 줘야만 tailnet에 들어올 수 있어서, Tailscale 서버나 계정이 뚫려도 가짜 PC가 들어오지 못합니다.

오크텀은 Tailscale 위에 자체 인증을 한 번 더 두므로(짝지은 기기 키만 통과) Tailnet Lock이 없다고 바로 뚫리는 것은 아닙니다. 그래도 겹겹이 막는 것이 목적이라, 회사 PC를 받는 쪽으로 켜는 분은 Tailnet Lock을 켜 두기를 권합니다. 켜는 방법은 Tailscale 문서의 Tailnet Lock을 따르세요.

준비 3 — ACL로 범위 좁히기

Tailscale의 접근 규칙(ACL)으로 집 PC가 회사 PC의 오크텀 포트 하나에만 닿게 좁힐 수 있습니다. PC에 태그(tag:home, tag:work)를 붙이고 태그끼리의 규칙을 씁니다. 태그는 관리 콘솔에서 PC에 붙이는 이름표입니다. 이름은 마음대로 정해도 됩니다.

{
  "tagOwners": { "tag:home": ["autogroup:admin"], "tag:work": ["autogroup:admin"] },
  "acls": [
    { "action": "accept", "src": ["tag:home"], "dst": ["tag:work:9620"] }
  ]
}

위 예시는 tag:home PC가 tag:work PC의 9620 포트로만 갈 수 있게 합니다. 핵심 한 줄은 {"src":["tag:home"],"dst":["tag:work:9620"]}입니다. 포트는 정식 빌드에서 9620입니다(개발 빌드는 9620에 인스턴스 번호가 더해집니다). 양방향으로 쓰려면 반대 방향 규칙을 한 줄 더 둡니다. 위 규칙은 기존 acls 배열에 한 줄을 더하는 것입니다. 기본 허용 규칙을 통째로 바꾸면 tailnet의 다른 통신이 끊깁니다. 또 PC에 태그를 붙이면 그 PC는 사용자가 아니라 태그가 소유하게 되어 다시 인증해야 할 수 있습니다.

짝짓기

짝짓기는 받는 PC 앞에 있는 사람이 직접 승인할 때만 됩니다. 원격에서 새 기기를 짝짓는 길은 없습니다.

  1. 받는 PC: 받기 켜고 짝짓기 창 열기

    설정 → 원격 접속 → 「이 PC로 원격 접속 받기」를 켭니다(Tailscale 주소가 표시됩니다). 「새 기기 짝짓기」를 누르고 Touch ID / Windows Hello로 본인 확인을 하면 2분 동안, 요청 1번만 받는 창이 열립니다.

  2. 하는 PC: 원격 PC 추가

    설정 → 원격 접속 → 「원격 PC 추가」에 받는 PC의 Tailscale 이름(또는 주소)과 알아보기 쉬운 표시 이름(예: 회사-Win)을 적고 요청합니다.

  3. 6자리 숫자를 비교하고 승인

    두 PC 화면에 같은 6자리 숫자가 뜹니다. 받는 PC에서 두 숫자가 같을 때만 「승인」을 누릅니다. 다르면 누르지 마세요 — 중간에 누가 끼어들었다는 뜻일 수 있습니다. 승인하면 양쪽 「등록 기기」 목록에 서로가 생깁니다.

등록 기기는 받는 PC의 설정에서 언제든 삭제할 수 있고, 삭제하면 그 기기의 현재 연결도 바로 끊깁니다.

메시지 — 허락은 보내는 쪽에서

  • 하는 PC의 에이전트가 chat_who를 부르면 짝지은 PC의 탭이 회사-Win / claude — 탭 이름처럼 나옵니다.
  • 처음 메시지를 보낼 때 보내는 PC(사람이 있는 PC)에서 허용 여부를 묻습니다. 받는 PC에는 허용창이 뜨지 않고 기록과 알림만 남습니다. 허용은 (내 탭, 상대 탭) 쌍마다 따로이고 앱을 다시 켜도 유지되며, 어느 쪽 탭이 닫히거나 기기가 삭제되면 사라집니다.
  • 대화는 하는 PC 쪽에서만 시작합니다. 받는 PC의 에이전트는 허용된 대화에만 답장할 수 있고, 먼저 말을 걸 수 없습니다. 받는 PC의 에이전트가 속아 넘어가도 하는 PC의 에이전트를 부릴 수 없게 하려는 장치입니다. 허용을 묻는 것은 보내는 쪽(하는 PC)의 사람이고, 거기서 거절하면 그 탭을 닫았다 열 때까지 최종입니다.
  • 받는 탭에는 from: 회사-Win / claude처럼 출처 PC 이름이 붙어 한 줄로 입력됩니다. 500자·제어문자 제거 같은 규칙은 로컬 채팅과 같습니다.
  • 상대가 오프라인이면 하는 PC → 받는 PC 메시지는 쌓지 않고 바로 오류(peer_offline)를 돌려줍니다. 반대로 받는 PC의 답장은 보관했다가(기기당 최대 500건·7일) 하는 PC가 다시 연결되면 한 번씩 전달합니다.
  • 메시지는 기기 쌍마다 분당 20건으로 제한됩니다(설정에서 바꿈).

파일

  • 에이전트가 chat_send_file로 파일 하나를 짝지은 PC로만 보냅니다(폴더 통째 전송·외부 주소 없음). 이름·크기·sha256이 받는 에이전트에게 한 줄로 전달됩니다.
  • 받은 파일은 받은편지함 폴더에만 저장됩니다: 데이터 폴더의 remote-inbox/<기기 이름>/<날짜>/. 자동으로 열리거나 실행되지 않고, 에이전트에게는 경로만 알려 줍니다. macOS는 「인터넷에서 다운로드한 파일」 경고, Windows는 「이 파일은 다른 컴퓨터에서 왔으므로…」 표시가 붙습니다.
  • 조각으로 보내고 끊기면 이어 받으며, 끝나면 sha256으로 확인합니다. 받는 PC의 디스크 여유가 부족하면 시작 전에 거절합니다.
  • 100 MiB를 넘는 파일은 사람이 있는 PC에서 한 번 확인합니다. 파일 하나의 한도는 기본 2 GiB(설정에서 낮출 수 있음)입니다.
  • 민감한 파일은 기본으로 막습니다. ~/.ssh, 클라우드·도구 자격 증명(~/.aws·~/.kube 등), 에이전트 설정과 토큰(~/.claude·~/.codex 등), 브라우저 프로필, 오크텀 데이터 폴더, .env·*.pem·id_* 같은 비밀값 파일이 해당합니다. 심볼릭 링크는 실제 경로를 따라가서 검사하므로 링크로 돌려서 보낼 수 없습니다.

본인 확인 — 12시간과 잠자기

  • 하는 PC에서 연결을 시작할 때마다 Touch ID / Windows Hello로 본인 확인을 합니다. 에이전트가 이 창을 대신 띄우는 일은 없습니다.
  • 확인은 12시간 유효합니다. PC가 잠자기에 들어가도 만료됩니다(깨어난 뒤 다시 확인). 화면 잠금은 만료 사유가 아닙니다 — 자리를 비워도 에이전트 일은 계속됩니다.
  • 만료되면 연결이 끊기고 상태바에 「본인 확인 필요」가 뜹니다. 그때 에이전트가 chat_send를 하면 auth_required 오류만 돌아옵니다. 상태바를 눌러 확인하면 다시 연결됩니다.
  • 확인이 유효한 동안 네트워크가 잠깐 끊겼다 돌아오면 확인 없이 자동으로 다시 붙습니다.

받는 PC의 잠금 화면

하는 PC가 연결되어 있는 동안 받는 PC의 오크텀 화면 전체가 「원격 사용 중」 잠금 화면으로 가려집니다(메시지가 터미널에 타이핑되는 모습이 사무실 사람에게 보이지 않게 합니다). 인앱 브라우저 화면도 함께 가려집니다.

  • 잠금 화면 아래에 「집-Mac 연결됨」처럼 연결된 기기 이름과 [모두 끊기] 버튼이 있습니다. 끊기는 본인 확인 없이 바로 됩니다. 끊으면 하는 PC는 스스로 다시 붙지 않고, 받는 PC는 60초 동안 그 기기를 받지 않습니다.
  • 받는 PC 앞에서 계속 쓰려면 [이 PC에서 계속 쓰기] → 이 PC에서 본인 확인. 풀어도 원격 연결은 유지됩니다.
  • 잠금 중에는 앱을 끌 수 없습니다(⌘Q·창 닫기 무동작). 풀거나 「모두 끊기」를 먼저 하세요.
  • 두 PC 앞에 다 사람이 있는 옆자리 테스트 같은 때를 위해, 기기별 「연결 중 화면 잠금」을 끌 수 있습니다. 끄는 일은 받는 PC에서만, 본인 확인 후에만 됩니다.

설정에서 볼 수 있는 것

설정 → 원격 접속에서 받기 켜기, 새 기기 짝짓기, 등록 기기 목록(마지막 연결·삭제), 원격 PC 추가, 메시지 속도·파일 크기 한도, 모든 연결 끊기, 감사 기록 보기를 합니다. 감사 기록에는 짝짓기·연결·끊김·본인 확인·메시지(본문은 저장하지 않음, 길이만)·파일(이름·크기·해시)·거절된 연결 시도가 30일 남습니다. 연결이 생기면 상태바에도 표시됩니다.

위험과 한계

집 PC가 장악되면, 그 PC의 에이전트가 할 수 있던 일을 공격자도 할 수 있습니다. 악성코드가 사용자 몰래 본인 확인을 통과할 수는 없지만, 사용자가 확인을 해 준 상태에서 장악된 PC는 정상 연결과 구분되지 않습니다. 그 PC의 에이전트가 허용된 대화로 회사 에이전트에게 일을 시킬 수 있고, 회사 에이전트가 읽을 수 있는 파일(차단 목록 밖)을 가져올 수 있습니다. 그래서 권한은 chat(메시지·파일)으로 좁게 두고, 위의 허용·속도 제한·잠금 화면·감사 기록으로 피해를 줄입니다.
  • Tailscale 계정에 2단계 인증을 켜고, Tailnet Lock·ACL로 범위를 좁히세요. 등록 기기를 잃어버렸다면 받는 PC에서 바로 삭제하세요.
  • 민감한 자료가 있는 PC는 이 기능을 켜지 않는 쪽이 가장 안전합니다. 받기는 기본 꺼짐입니다.
  • 회사 PC에 켜기 전에 회사 정책을 확인하세요. 사내 PC에 외부 PC의 접속을 받는 것을 보안 정책이 금지하거나 사전 승인을 요구할 수 있습니다. 허락 없이 쓰다 문제가 되는 책임은 사용자에게 있습니다.
  • 상대 PC와 오크텀 버전(원격 프로토콜)이 다르면 연결이 거절되고 「상대 PC 업데이트 필요」가 나옵니다.
