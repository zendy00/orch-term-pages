Release · Changelog

Changelog

New features and fixes per version. With auto-update (since v0.1.23) on, a new release is announced via a titlebar banner and installed in one step. Each release note is generated automatically from Conventional Commits.

Legend — feat new feature · fix bug fix · perf performance. Dates are based on the tag creation date.

0.9.0 — Terminals survive app updates and restarts · keep or close them when you quit

v0.9.02026-09-18Latest
  • featYour terminals keep running when you update or restart the app — shells, running builds and servers, AI agents, and scrollback all carry on, and each tab reattaches to its original shell when you reopen the app. The same holds if the app crashes. A background process (orchterm-ptyd) now holds your terminals, so seeing that name in Activity Monitor or Task Manager is normal
  • featChoose what happens to running terminals when you quit — closing the window, or pressing ⌘Q on macOS, asks you to Keep running in background / Close all / Cancel. "Don't ask again" remembers your choice; change it back in Settings → Terminal. If the app stays closed for 24 hours, background terminals are cleaned up
  • featUpdates that change the terminal service warn you before installing — in the rare case an update can't keep your terminals running, you're told "the N running terminals will close" first (Auto-update). Regular updates leave your terminals alone
  • featIf a terminal can't start, the tab shows why and where the log is — instead of staying blank
  • fixFixed Korean characters being typed twice after a space on macOS — 개 발 became 개 개 발 발 until the Mac was rebooted. When the macOS Korean input method switched to committing the space together with the syllable, the space arrived as a different kind of space character and was sent twice. Input now arrives once in either mode
  • fixFixed stray characters such as ^[[I^[[?1;2c after reloading the window — automatic replies the terminal sends while redrawing the previous screen were leaking into the shell

⚠️ Terminals that are open when you update to 0.9.0 will not carry over — the previous version held terminals inside the app itself, so it can't hand them off. AI agent conversations reopen after the restart. Terminals survive starting with the next update.

0.8.3 — macOS local network access · accurate memory figure

v0.8.32026-09-16
  • fixFixed the terminal being unable to reach servers on your local network on macOS — commands like curl http://internal-host:3000 failed immediately. macOS grants local network access per app, and orchterm never requested it, so it was denied silently. It now requests the permission properly, and once allowed the grant survives updates
  • fixFixed the macOS status bar memory figure disagreeing with Activity Monitor by more than 1GB — it now counts the same way as "Memory Used"

macOS builds are now code signed (needed for the local network permission to survive updates). Apple notarization is still pending, so the first-launch prompt is unchanged.

0.8.2 — Fixed in-app browser tabs opening blank

v0.8.22026-09-09
  • fixFixed in-app browser tabs opening to a blank screen — the address stayed in the address bar but the page never appeared, and once it happened every tab opened afterwards behaved the same way (until a restart). Not site-specific; local development server addresses were affected too. The cause: with mirror on and at least one AI session attached inside the app, every new tab was left suspended before it could start drawing the page. The app now releases that suspension itself — covering links clicked in the terminal, tabs opened by an AI, and setups with several Spaces

0.8.1 — Six workers · long jobs no longer cut off · orchestration hardening

v0.8.12026-09-07
  • featSix agents can be put to work — Grok·opencode·Hermes join Claude Code·Codex·Antigravity. The list shows only what is actually installed, so no turn is wasted spawning a worker you don't have
  • featHand a worker jobs that take minutes — long work used to get cut off by the directing AI's time limit (60s with Claude Code), and retrying delivered the same instruction twice. Work is now handed over and checked on in short intervals, so refactors, reviews and builds run to completion
  • featGrok·opencode·Hermes icons in the session list — all six CLIs are distinguishable at a glance
  • fixFixed worker replies arriving at the wrong place, or coming back empty — with more than one similarly-named orchterm running, a worker could report to the instance that didn't spawn it, leaving the side that assigned the work with messy scraped text. Workers are now told exactly where to report
  • fixFixed a Codex worker dying on startup (no pty session) — its update prompt was mistaken for the input line, Enter selected "update now" and Codex quit. Startup prompts are now recognised and reported (without closing the tab or answering for you)
  • fixFixed opencode workers taking 30 seconds to start — the readiness signal was being read incorrectly
  • fixFixed leftover development registrations causing connection-failure warnings every time you ran Codex or Claude — dead registrations are cleaned up at startup

If you use Hermes — Hermes cannot answer at all once its configured model becomes unavailable (subscription change, model retirement). Pick a working model with hermes model and register a spare with hermes fallback add, and it will switch over automatically later.
